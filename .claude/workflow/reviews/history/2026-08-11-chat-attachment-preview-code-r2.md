Live-proven: running the test's exact insert pattern yields `owner=Administrator`, and `get_canvas` returns `PermissionError: not your conversation` (the ownership message), not `no permission to read this file` (the gate message). | Make the conversation genuinely owned by the restricted user so the ownership gate passes and the File-read gate is reached — e.g. `frappe.db.set_value(CONV, conv.name, "owner", USER)` after insert (verified live to then hit the gate), or build it while `frappe.set_user(USER)`. Add a precondition assertion that the restricted user OWNS the conversation, and assert the raised error is the file-gate error (message/`get_canvas` reaching line 703) — not the ownership error — so the test cannot silently regress to the wrong gate again. |
